# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this
project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0,
minor versions may contain breaking changes.

## [Unreleased]

### Added

- Ed25519 key files, key ids and domain-separated detached signatures with strict
  verification.
- Trust stores of `prod-*` and `dev-*` public keys that fail closed on misnamed or duplicate
  keys.
- `manifest.json` model with parsing and semantic validation.
- Streaming `verify`, `verify_and_extract`, `verify_head` and `inspect` for `.homing`
  packages (tar, optionally zstd), with hostile-archive tests.
- Deterministic `PackageWriter`.
- Device compatibility checks (`engine.json`) and anti-rollback floors.
- Shared error codes (`E_SCHEMA`, `E_SIG`, `E_HASH`, ...).
- Signed update index (`index.json` + `index.json.sig`): `Index`, `verify_index` and
  `Index::select`, which picks the newest build compatible with a device.
- `DeviceInfo::check_compat` for checking compatibility fields outside a manifest.
- Constructors for the data types (`Manifest::new`, `Compat::new`, `Runtime::new`,
  `FileEntry::new`, `DeviceInfo::new`, `Index::new`, `IndexApp::new`, `IndexBuild::new`) and
  a builder for `VerifyOptions` (`VerifyOptions::new(&trust).device(&d).floor(n)`).
- Language-neutral test vectors in `test-vectors/` (every verifier error code, plus signed
  indexes with expected selections), generated by `cargo run --example gen-vectors` and
  checked in CI.
- `SecretKey::to_file_string`.
- JSON Schemas (draft 2020-12) in `schemas/` for `manifest.json`, `*.sig`, `engine.json` and
  `index.json`, tested to agree with the parsers.
- Fuzz targets (`fuzz/`) for manifest, signature, index and path parsing, package
  verification, and extraction (which must never write outside the staging directory). CI
  runs them on every push to `main` and longer each week.

### Changed

- Public data types and enums that may grow are `#[non_exhaustive]`, so new fields and
  variants can be added in minor releases. Build them with the constructors; fields remain
  public for reading and writing.

### Fixed

- A file outside `bundle/`, `config/` and `sbom/` is now reported as `E_PATH` (was
  `E_EXTRA_FILE`), consistent with directories.
